# agents_skills

Переносимые скиллы для AI-агентов: персональный дневник питания и тренировок с четырьмя модулями и независимый собеседник `objective-partner` v2.0. Каждый пользователь подключает своё хранилище и настраивает свой профиль.

В репозитории находятся инструкции, справочники, пустой шаблон и вымышленные проверочные сценарии. Личные профили, дневники, медицинская история, подключения и ключи сюда не входят.

## Состав

| Каталог | Назначение |
|---|---|
| [maintain-nutrition-training-diary](maintain-nutrition-training-diary/README.md) | Основной скилл дневника v1: настройка, записи, исправления, итоги и маршрутизация модулей |
| [nutrition-and-energy-balance](nutrition-and-energy-balance/README.md) | Порции, КБЖУ, рацион и энергетический баланс |
| [training-plan-and-progress](training-plan-and-progress/README.md) | Силовые, общая нагрузка, восстановление и прогрессия |
| [freediving-training-profile](freediving-training-profile/README.md) | Апноэ и фридайвинг: сессии, техника, серии и совмещение нагрузок |
| [scientific-source-verification](scientific-source-verification/README.md) | Научные ссылки, библиография и применимость утверждений |
| [objective-partner](objective-partner/README.md) | Независимая проверка рассуждений, неопределённости и дрейфа контекста |

Дневник — комплекс из пяти соседних папок. Для полного комплекта устанавливайте все пять. `objective-partner` работает независимо и не требует дневника.

## Что требуется

- AI-агент, умеющий читать `SKILL.md` и связанные файлы. Скиллы задают процедуру; сам репозиторий не является готовым приложением или сервером.
- Для сохранения дневника — доступ агента к выбранному пользователем хранилищу. Новый дневник по умолчанию создаётся как нативная Google Sheets через подключённые инструменты Drive/Sheets. Уже выбранный формат сохраняется; поддерживается и явно выбранный XLSX при наличии инструментов чтения и записи файлов.
- Для фотографий — просмотр изображений/OCR. Для новых научных сведений — поиск и чтение первоисточников. Без доступа к записи агент может разбирать данные в чате, но не должен подтверждать их сохранение.
- Необязательный библиографический скрипт требует Python 3.10+ и сеть. Остальным инструкциям Python для установки не нужен.

## Установка в Codex

Склонируйте репозиторий или используйте уже имеющийся клон:

```sh
git clone https://github.com/kantram7/agents_skills.git
cd agents_skills
```

Согласно [официальной документации OpenAI](https://learn.chatgpt.com/docs/build-skills), локальные скиллы Codex можно размещать в `~/.agents/skills` для пользователя либо в `.agents/skills` целевого проекта. Каждая папка скилла копируется целиком, со справочниками и ресурсами. Сохраните имена и соседнее расположение пяти папок дневника.

Пример для PowerShell из корня клона; установит оба комплекта для текущего пользователя и остановится, если одноимённая установка уже существует:

```powershell
$skillNames = @(
  'maintain-nutrition-training-diary',
  'nutrition-and-energy-balance',
  'training-plan-and-progress',
  'scientific-source-verification',
  'freediving-training-profile',
  'objective-partner'
)
$skillsDestination = Join-Path $env:USERPROFILE '.agents/skills'
foreach ($skillName in $skillNames) {
  $installedPath = Join-Path $skillsDestination $skillName
  if (Test-Path -LiteralPath $installedPath) {
    throw "Уже установлено: $installedPath. Сначала сравните версии и сделайте резервную копию."
  }
}
New-Item -ItemType Directory -Path $skillsDestination -Force | Out-Null
foreach ($skillName in $skillNames) {
  Copy-Item -LiteralPath (Join-Path $PWD $skillName) -Destination $skillsDestination -Recurse
}
```

Для одного `objective-partner` оставьте только его имя в списке. Если скиллы не появились в выборе после копирования, перезапустите Codex. Не устанавливайте одновременно несколько копий с одинаковыми машинными именами.

В другом агенте используйте поддерживаемый им каталог скиллов или попросите прочитать нужный `SKILL.md` и доступные ссылки. Копирование файлов не подключает Google, не выдаёт доступ к прошлым чатам и не включает скилл автоматически во всех сервисах. Для ChatGPT нужен поддерживаемый механизм импорта/установки; репозиторий сам по себе не является зарегистрированным плагином.

## Быстрый запуск

Создать свой дневник:

```text
Используй $maintain-nutrition-training-diary.
Помоги настроить новый дневник под меня в моей Google-таблице.
Сначала уточни только недостающие данные и место хранения профиля.
```

Подключить существующий:

```text
Используй $maintain-nutrition-training-diary.
Подключи выбранный мной дневник, сохрани его структуру.
Профиль храни отдельно от инструкций скилла и публичного репозитория.
```

Запустить независимую проверку:

```text
Используй $objective-partner. Проверь мой план и основные предпосылки.
Не возражай ради спора; отдели подтверждённое от предположений.
```

Подробности: [настройка и примеры дневника](maintain-nutrition-training-diary/README.md), [команды objective-partner](objective-partner/README.md).

## Разделение инструкций и данных

```text
Публичный репозиторий            Приватное хранилище пользователя
SKILL.md, references/, assets/   заполненный профиль и персонализация
пустой profile.example.yaml      записи, измерения и медицинская история
вымышленные сценарии             ID дневника и настройки доступа
```

Скопируйте [пустой шаблон профиля](maintain-nutrition-training-diary/assets/profile.example.yaml) за пределы репозитория перед заполнением. `null` означает неизвестное. Ни вид спорта, ни масса тела, ни рацион, ни цели не наследуются от автора. Секреты храните в защищённом подключении, а не в профиле.

`.gitignore` исключает распространённые локальные файлы, но не заменяет эту границу: не добавляйте личные данные в отслеживаемые инструкции или шаблон. Обновляйте инструкции отдельно от личного профиля. Установленные копии обновляются отдельно от `git pull` в клоне.

## Проверки и ограничения

[Проверка комплекта](scripts/validate_bundle.py):

```sh
python scripts/validate_bundle.py
python -m unittest discover -s tests -v
```

Проверяются структура, локальные ссылки, пустой профиль, комплектность модулей и отсутствие ссылок на персональные хранилища. Модульные тесты библиографического скрипта работают на макетах без сети. Ручные поведенческие проверки: [дневник](maintain-nutrition-training-diary/references/scenarios.md), [фридайвинг](freediving-training-profile/references/scenarios.md), [objective-partner](objective-partner/TESTS.md). Автоматическая проверка файлов не доказывает качество всех будущих ответов агента.

Скиллы не предоставляют медицинскую квалификацию, не управляют тренировкой в реальном времени и не подключают часы, таймеры или сервисы без отдельной интеграции. Рекомендации зависят от доступных фактов; неизвестные данные остаются неизвестными. Для водного апноэ сохраняются профильные требования страховки.
